# 2026 至 2027 年佛教月历订阅

将月历中的历法日期、佛菩萨纪念日、荟供日、理发吉日和其他标记整理为 Apple 日历可订阅的 ICS 文件。订阅后可直接在日历中查看，并接收指定类型日子的提醒，无需安装额外应用。

[打开订阅页面](https://cdu445.github.io/calendar2027/) · [查看提醒日期清单](REMINDERS.txt)

## 日期范围与内容

当前覆盖 **2026 年 11 月 1 日至 2027 年 12 月 31 日，共 426 天**。

- 2026 年 11、12 月：按附件提供的公历、藏历和备注整理，不补填原稿没有的农历。
- 2027 年全年：包含原稿中的农历、藏历、节日、修持事项和理发吉日等文字。
- 每天以一个全天事件呈现，备注保留来源文件名及页码。
- 藏历的重日、缺日和闰日按原稿保留，不按公历推算补齐。

2027 年内容来自扫描件，仍可能存在文字识别错误；图形标记可能未完整转为文字，重要日期请核对原始月历。宗教历法中的说明作为来源内容保留。

## 特殊日期提醒

两个版本都为下列四类日期设置 **前一天上午 9 点**的显示提醒：

| 提醒类型 | 当前匹配天数 | 匹配范围 |
| --- | ---: | --- |
| 空行荟供日 | 15 | 包括空行母、空行佛母荟供日 |
| 理发吉日中怀业增上 | 13 | 仅理发吉日文字中含“怀业增上”的日期 |
| 莲师荟供日 | 14 | 包括莲花生大士荟供日，不仅凭诞辰名称匹配 |
| 八吉同聚日 | 37 | 原稿中的八吉同聚标记，不含九凶同聚日 |

同一天命中多类只设置一个提醒，合计 **75 个提醒日期**。其他日期未在数据源中加入提醒；Apple 日历自身的默认提醒设置可能另行影响显示。完整日期见 [REMINDERS.txt](REMINDERS.txt)。

提醒相对于全天事件开始时间提前 15 小时，通常对应日历所用时区的前一天上午 9 点。实际通知取决于客户端对订阅提醒的支持、通知权限、专注模式和设备设置。已过去的提醒时间不会作为可靠的补发通知。此订阅不能替代必须准时响起的闹钟。

## 在 Apple 日历中订阅

### Mac

1. 打开“日历”应用，选择“文件 → 新建日历订阅”。
2. 粘贴上表中的一个 HTTPS 订阅地址，点击“订阅”。
3. 如需在其他 Apple 设备查看，位置选择 iCloud，并在设备上使用同一 Apple 账户。
4. 自动刷新可选择“每天”。如要接收内置提醒，取消“移除提醒”等相关选项的勾选。
5. 保存后，打开一个未来的提醒日期，检查事件信息中的提醒时间。

### iPhone 或 iPad

打开订阅页面，点选需要的版本并按系统提示添加。也可在“设置”中搜索“日历账户”，从添加账户的“其他”选项中选择添加已订阅的日历，粘贴 HTTPS 地址；不同系统版本的入口名称可能有差异。

在“日历”应用的日历列表中，轻点该日历旁的 ⓘ，如有“日程提醒”选项，请开启；如有“移除提醒”或“忽略提醒”，请关闭。同时在系统通知设置中允许“日历”发送通知。

这里需要添加的是**订阅**。将下载的 ICS 一次性导入日历，不会持续获取本项目的更新。

## 更新与刷新

维护者更新同一地址下的文件后，订阅者会在客户端下一次抓取时获取新版，通常无需重新订阅。“每天刷新”控制数据更新频率，与指定日期的通知提醒是两项独立设置。

- iPhone 或 iPad：打开“日历”，进入日历列表，下拉后松手刷新。
- Mac：选择“显示 → 刷新日历”。

GitHub Pages 发布、网络缓存及客户端抓取都可能造成延迟。若看不到更新，先确认仓库的 Pages 部署已成功，再检查网络及订阅地址。

## 文件说明

| 文件 | 用途 |
| --- | --- |
| `calendar.ics` | 完整月历订阅源 |
| `special.ics` | 节日与事项订阅源 |
| `index.html` | 浏览器中的订阅入口 |
| `README.md` | 仓库首页功能与使用说明 |
| `REMINDERS.txt` | 所有提醒日期及分类清单 |

GitHub Pages 提供静态 HTTPS 文件服务，日历读取不连接 NAS，NAS 无需为此保持运行。当前版本不包含用户提交表单，也不要求订阅者向本站提供账号或密码。日历文件和仓库内容公开可读取。

## 维护者更新方法

1. 准备生成好的新版文件，核对内容、日期数量和提醒清单。
2. 在原仓库点击“Add file → Upload files”，将新版文件上传到根目录，覆盖对应同名文件。
3. 填写本次修改说明并提交至用于 Pages 发布的 `main` 分支。
4. 在仓库“Actions”中等待 Pages 部署成功，打开订阅页面及 ICS 地址验证结果。
5. 保持 `calendar.ics`、`special.ics` 的路径和已有事件 UID 稳定，以便客户端更新；内容更新时同步修改版本时间及说明。

现有 GitHub Pages 配置使用 `main` 分支、`/ (root)` 目录。更新文件时通常无需更改 Pages 设置。不要把 NAS 的 `.env`、密码、令牌或部署目录上传到这个公开仓库。

订阅者更改本机提醒选项不会修改数据源；分类和提醒时间由维护者统一调整。本项目目前只覆盖上述日期范围，不会自动生成 2028 年及以后的日历。
